Mini Split 计算器页面：Shopify 上线指南

这份指南讲清楚三件事：现在东西在哪、怎么把它放上 dellahome.com、哪些地方千万别碰。照着一步一步做就行。

一、先搞清楚：现在东西在哪，是什么状态

代码放在哪：GitHub 仓库 github.com/cleopatrahines/della-pages。可以把 GitHub 想象成一个"存代码的网盘"，里面 mini-split-sizing-calculator 文件夹就是这个项目的全部东西。

现在是什么状态：目前做好的是视觉稿（就是你在 cleopatrahines.github.io 上看到的那个页面）。它是给人看效果、提意见用的样品，不是能直接上架的正式版。

最重要的一句话：不要把视觉稿的 HTML 直接复制粘贴到 Shopify 里。视觉稿里塞了开发用的测试数据（写死的产品、评论、地图），直接贴上去将来没法维护，样式还会和主题打架。正式上线要用下面说的"正式版三件套"。

二、上线的整体路线（两大步）

1先做正式版（这一步交给 Claude 做）。视觉稿定稿后，Claude 会把它改造成 Shopify 认识的格式，叫"正式版三件套"：
东西是什么放到 Shopify 哪里
1 个 section 文件（.liquid）页面的骨架主题的 Sections 文件夹
几个资源文件（.js / .css / .json）计算器的大脑和皮肤主题的 Assets 文件夹
1 个页面模板告诉 Shopify 这个页面长什么样Templates 文件夹
你们店里已经上线的 HVAC Product Finder 用的就是这个套路，照方抓药，风险最小。
2再把三件套装进 Shopify（这一步你在后台点几下就行）。具体步骤看下一节。

三、手把手：把正式版装进 Shopify 后台

动手前必做的保险动作：复制一份主题。路径：Shopify 后台 → Online Store → Themes → 在当前主题右边点 … → Duplicate。所有改动先在这个副本上做，确认没问题再发布。这样就算改坏了，正在营业的网站一根汗毛都不会少。
1打开 Online Store → Themes，找到刚复制的副本主题，点 … → Edit code（编辑代码）。
2左边找到 Sections 文件夹 → 点 Add a new section → 起名 mini-split-sizing-calculator → 把 Claude 给你的 .liquid 文件内容整个粘贴进去 → 点 Save。
3左边找到 Assets 文件夹 → 点 Add a new asset → 把 Claude 给你的 .js、.css、.json 文件一个一个上传进去。
4回到 Shopify 后台首页，进 Online Store → Pages → 点 Add page → 标题填 Mini Split Sizing Calculator → 右侧模板（Theme template）选 Claude 给你的那个新模板。
5右下角确认网址（URL handle）是 mini-split-sizing-calculator，页面先设为 Hidden（隐藏），点 Save。
6点页面上的 Preview（预览）自己检查一遍，对照下面第四节的清单。
7都没问题后：把页面从 Hidden 改成 Visible（可见）；如果前面用的是副本主题，去 Themes 里把副本 Publish（发布）成正式主题。上线完成。

四、上线前的检查清单（一条条对着勾）

□ 电脑上打开页面，输一个真实邮编（比如 40202），看气候区提示对不对

□ 改动面积、保温这些选项，看推荐结果会不会跟着变

□ 点 Find Matching Products，确认跳到的搜索结果里是对应 BTU 的产品而且有货

□ 点多区域那行小字，确认搜索结果里出现多联套装

□ Top Sales 的加购按钮点一下，确认商品真的进了购物车

□ 用手机打开一遍：表单好不好填、评论能不能左右滑

□ 页面标题和描述（SEO）：Pages 编辑页最下面 Edit website SEO，确认标题含 "Mini Split Sizing Calculator"

五、千万别碰的东西

别动 theme.liquid、header、footer 这些带"主题命脉"性质的文件——这个项目根本不需要改它们。
别在正式主题上直接试验。永远先复制主题（见第三节开头）。
别手改注入产物。以后想改文案、改样式，回到 GitHub 仓库改源文件（或直接让 Claude 改），改完重新走一遍上传。直接在 Shopify 里手改，下次更新会被覆盖。

六、已知的坑（上线时逐条核对）

字体：页面用 Spectral + Inter（站内 PageFly 已托管），新页面若字体没生效会退回系统字体、观感大变。
解决：正式版的 CSS 里会直接声明站内已托管的字体文件（@font-face 指向 PageFly 的 woff2 地址），不依赖别的页面加载。上线预览第一眼看标题是不是衬线体，不是就把截图发给 Claude，一处 CSS 就能修。
ZIP 数据体积：完整气候数据 33,784 个邮编约 540KB，不适合整包塞进主题 assets 让每个访客下载。
解决（已定方案，实测验证）：用前缀索引精简版——896 条三位前缀主值 + 2,808 条例外全量保留，实测 57KB（传输时 gzip 后仅 10KB，一张小图的体积），任何 ZIP 的查询结果和完整版一字不差（100% 精确）。直接作为一个 JSON 上传到主题 assets 即可，不依赖任何外部接口、不需要任何额外权限、没有维护成本。压缩脚本已在仓库里，正式版打包时 Claude 自动生成。
（说明：站内 HVAC Finder 有个 Vercel 气候接口，但那是领导团队的部署且只返回区域标签、没有本计算器需要的设计温度，不适用也无权限，不作为方案。）
气候地图口径：页面五色地图是州级简化示意和未输入 ZIP 时的 fallback，不是 DOE/IECC 1–8、A/B/C 官方县级地图。
解决：保留地图下方的简化说明，不要宣传为官方气候区地图；正式版以 ZIP 对应的县级气候资料为主，地图点击只给区域级估算。
Loox 评论组件：需要显示全店评论（4.9/1702）而不是某个商品的评论。
解决：后台路径 Apps → Loox → Widgets，确认 Store Reviews（全店评论）组件已开启；嵌入代码里必须带 data-loox-aggregate 属性（our-reviews 页面用的就是这个写法，直接照抄它的嵌入块最稳）。嵌入后刷新页面核对头部是不是 4.9 分 1,702 条。
搜索链接依赖：Find Matching Products 依赖站内搜索对 "12000 BTU" 和 "12K" 的命中规律。
解决：验证方法=在站内搜索框分别搜 "12000 BTU"（应出单机）和 "12K"（应出带 12K 头的多联套装），上线检查清单里已包含。以后如果装了搜索类 app（Boost 等）或改了产品命名规范，重跑一遍这个验证；万一命中规律变了，把按钮链接改成对应 BTU 集合页（如 /collections/12000-btu-mini-split）作为兜底，Claude 改一行模板即可。
埋点：页面里的 track() 事件（计算完成、点击找产品、加购）目前是空壳，不接上就没法评估这个页面赚不赚。
解决：正式版由 Claude 把 track() 映射到 GA4 的 dataLayer（店铺已装 GA 的话零配置，事件名就用 btu_calculator_completed / matching_product_clicked / add_to_cart_after_calculator 三个）。上线当天验证方法：打开 GA4 的 Realtime 报告，自己在页面上算一次、点一次按钮，看这两个事件有没有跳出来。
Top Sales 的加购按钮：视觉稿里写死了抓取时的 variant ID，产品改版或下架后按钮会失败。
解决：正式版由 Claude 改为 Liquid 动态读取（all_products[handle].first_available_variant），产品信息永远和店里同步，写死 ID 的问题在正式版根本不存在。
多联档搜索链接未实测：36K 以上六个容量档（38000/41000/42000/45000/48000/55000 BTU）的搜索命中只核对过产品标题含这些词，没在线上搜过。
解决：上线检查时在站内搜索框把六个词各搜一遍确认出产品；哪个词命不中，就把那一档改成对应集合页链接，Claude 一行模板改完。

七、出了问题怎么办

页面显示不对：先别慌，页面设回 Hidden（顾客就看不到了），然后把截图和问题描述发给 Claude。
整个主题出问题：去 Themes 把之前的正式主题重新 Publish，网站立刻恢复原样。这就是为什么第三节坚持要你先复制主题。
评论板块：正式版会直接用店里已装的 Loox 应用的官方组件（就是 our-reviews 页面那个），评论自动更新，不用人管。
